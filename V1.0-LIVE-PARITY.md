## Candidate versus effective live render

The fresh post-merge raw scalar comparison contains 220 paths:

- Before applying canonical runtime isolation, 63 paths are build-context,
  bind-source or the equivalent `x-stexor-node-app` source anchor. They reflect
  the fresh platform/application checkout roots versus the current live
  checkout/hotfix roots. The other 17 paths are the intentional functional
  differences enumerated below. The tracked Traefik static file,
  admin/project routes and both WAF files were byte-matched against their
  active live sources.
- 140 net paths come from the canonical `compose.runtime-isolation.yaml`
  overlay omitted by the one-off fresh-runtime render. The overlay adds 143
  resource/isolation fields and supersedes three build-context scalar paths:
  exact CPU/memory/PID/ulimit/blkio budgets across the 20 core/admin services,
  image-only execution for Control Center, project router and alert dispatcher,
  read-only/tmpfs controls for the two request-facing services, and the four
  `x-runtime-*` policy maps. These are intentional tracked hardening, not live
  state to preserve.
- The live middleware uses `referrerPolicy: same-origin`; the candidate keeps
  the stricter canonical `no-referrer`. This is an intentional security
  correction, not missing live state.
- The external `runtime.env` originally resolved the candidate Control Center
  CA mount to the server leaf certificate. It was backed up and corrected to
  `certs/ca.pem`; the regenerated render now matches the running CA source.
- The candidate removes the runtime dependency from Control Center to
  Keycloak because active authentication is PostgreSQL-backed `app-passkey`.
- The candidate narrows first-configuration access from all RFC1918 ranges to
  the actual LAN `192.168.1.0/24` plus loopback.
- The candidate adds bounded backup-queue defaults and the direct backup jobs
  directory already consumed by the current Control Center code.
- The candidate image name is the canonical local build tag instead of the
  ad-hoc live hotfix tag.
- The live database-admin hotfix made phpMyAdmin and phpPgAdmin profileless.
  The candidate preserves the exact `admin` gate and the LOCAL_PRIVATE wrapper
  enables that profile itself; caller-controlled profiles remain forbidden and
  the VPS render never enables it. Both services remain in the 32-service
  reproducible topology without becoming default services in other modes.
- The project router binds the corrected canonical LOCAL_PRIVATE workload-lock
  SHA instead of the stale pre-parity live-observed lock SHA.
- NATS uses the image-absolute `/nats-server`; the live hotfix invokes the same
  binary through `PATH`.

The running Keycloak container still has an obsolete
`platform-first-configuration` theme bind mount. It is absent from the
effective Compose render and is not an intentional V1 dependency. It must be
removed by a controlled Keycloak recreate after the new main is available;
the theme is not imported as source authority.

A scoped security review compared the candidate with every non-dependency file
inside the running Control Center. The exact delta is ten modified files plus
the live-only migration 005. With the observed `app-passkey` mode, direct first
configuration returns before the Keycloak adapter/store/config path, the
handoff route is disabled and `/auth/callback` is not exposed. Migration 006,
not migration 005, owns the active passkey tables. The legacy handoff bytes and
their existing PostgreSQL rows are therefore preserved as external historical
state but are not imported as intentional V1 software.
